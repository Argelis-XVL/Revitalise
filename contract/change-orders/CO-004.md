## Scope — two increments priced together, a third priced separately and later

Per the reviewer's routing (`docs/plans/emily-review-feedback-2026-09-plan.md` line 1102, Δ4, and
line 1262, §5b pricing table), the source has moved from Emily's spreadsheet export to ONS's own
`ONSPD_LATEST_UK` endpoint (OGL v3 licensed). Three increments are priced separately, not the file:

1. **A generator** that seeds the existing outward-code shape (the same shape as
   `PostcodeRegionMap`) with local-authority names from the `LAD26CD` → `LAD26NM` register, flagging
   every outward code that spans more than one local authority rather than silently picking one.
2. **The unit-postcode lookup** — **not priced by this document.** Sized **L** in the plan (line
   1262) as a later decision Revitalise can take once this increment's numbers exist. Left as a
   flagged follow-on.
3. **The quarterly-refresh scheduled job** that keeps the register current — priced together with
   increment 1 per the plan's explicit instruction ("price these two together", line 1262).

This document prices increments 1 and 3 only.

## Why this is a change order, not rework against an existing task

No task in `contract/wbs.json` names a local-authority reference table or a scheduled refresh job.
`PostcodeRegionMap`'s existing shape (outward code → region) is a WBS v0.5 deliverable already built;
adding local-authority names and a maintenance job to it is new capability with an external
dependency (ONS's endpoint) — the plan's own `L`-class marker for new capability, even though this
piece is priced `M`. Plan citations: line 1102 (EF-41 detail, Δ4) and line 1262 (§5b pricing
summary).

## What this explicitly does NOT price — EF-49 stays out

Loading this reference table also happens to repair region derivation for five postcode prefixes
(`BB`, `CT`, `HP`, `PE`, `WD` — `logs/known-failure-modes.md` line 535) because the existing
"longest-prefix-wins" lookup silently degrades to a shorter prefix instead of resolving to "Not
known". **That fix is EF-49, a live defect against a contracted deliverable already `in-baseline`,
not new capability** (plan line 1119, and explicitly: "Do not bundle it into EF-41's change order").
It is unaffected by this document and is not re-priced here.

## One carve-out this increment does not resolve

Northern Ireland's 99 BT districts need a licence answer from Revitalise (Land and Property
Services) before they can be regenerated from ONSPD. Increment 1 leaves them flagged and untouched;
this document does not price a BT-district regeneration and none is scheduled until that licence
question is answered (plan line 1102, "One carve-out").
