## Scope

Four DocuSign template anchor tabs on the referee (Signer 2) side of the Grant Acceptance
envelope — `t2` (Title), `a2` (Address), `c2` (Town/City), `pc2` (Postcode) — currently prefill
from nothing, because no field on `rev_application` or any other Dataverse table captures them.
The reviewer has asked that these four be captured as new schema so the referee side prefills
fully, same as the Grant Acceptor (Signer 1) side already does.

## Why this is a change order, not in-scope build

`contract/wbs.json` task `wbs:3.2` ("Build trigger flow") scopes creating a DocuSign envelope
"with pre-populated fields" from **data that already exists** — it does not scope capturing new
data. No task in automation 3 (3.1–3.7) or the data-model tasks under automation 0 (`wbs:0.4`,
which lists the seven built tables — Applicant, Application, Review, Grant, Provider, Bank
Account, Payment — and names no Referee table or referee columns) covers collecting a referee's
title, address, town/city or postcode anywhere. Automation 1 (Form Validation & Completeness,
`wbs:1.1`–`1.6`) governs the applicant-facing form spec and also names no referee fields. The
string "referee" does not appear anywhere in `contract/wbs.json`, `contract/known-exceptions.json`
or `contract/service-agreement.json` — this is new scope, not an ambiguity in an existing task's
wording (same test CO-001 applied).

## Why this needs architect-agent before it needs a figure

This is not a same-shape repeat of CO-001 (which was one screen, sizeable by analogy to two
comparable tasks). Where these four fields are captured changes what is being priced:

- **Captured at referee intake** (the natural place a referee would supply their own title/
  address, likely alongside however the referee's identity/contact details already reach the
  process) — touches automation #1's form design and whatever referee-facing intake exists
  today, which is not itself named in the current WBS either.
- **Captured on `rev_application` directly, entered by the applicant or staff on the referee's
  behalf at the point of prefill** — a narrower, `wbs:3.2`-adjacent schema addition only.
- **Captured on a new/extended referee-specific entity** — a data-model shape decision, not a
  column-count one.

Each shape carries different hours and different downstream implications (validation, who can
edit the data, whether it round-trips into any existing referee correspondence). Per this
project's rule that an FR with no comparable existing WBS task is the flag that a by-analogy ROM
undercounts, guessing a figure now — before the shape is chosen — risks the exact CO-001 defect
this project already logged once (`IMP-0288`).
