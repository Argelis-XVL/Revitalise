## Scope

1. Rewrite the description of every row in the live settings table, which the reviewer states holds **50** (2026-10-23, quoted from his own turn), in plain language for the process owner: what the setting is for and how the system uses it. No requirement, decision-record or document ids, and no pointers to documents the process owner cannot open. Applied to the 48 rows in all three environment files (`dev-scoring`, `test`, `prd` under `provisioning/deploymentSettings/`).
2. A new global choice set for setting category and a new Choice column `Category` on `rev_setting`. Each of the 50 rows gets a category value. The Settings view is sorted by category and the column is shown so the user can group by it.
3. The seeding script must reach the 16 rows marked `createOnly`, which it never writes again after creation. Without that, an existing environment keeps the old description and gets no category on those rows (KnockoutThreshold, the band and income settings, the Redaction* settings, the five AmountLimit* settings and the two rule switches). Description and category only; the process owner's value is never touched.

**Not part of this order:** changing any setting's value, name or data type; new settings; a new view type or app page; translating descriptions.
