# CO-003 — County for the Grant Admin App (EF-40, new column)

**Status:** APPROVED
**Approved:** 2026-09-18 — Anna Southern (reviewer), exact words "APPROVE CHANGE ORDER CO-003,"
approved as drafted, relayed by lead-agent alongside CO-004 and CO-005.
**Raised by:** commercial-agent, `feature:grant-admin-app`, per C-COM-002
**Feature:** grant-admin-app

## Scope

A genuinely new column on the Applicant entity — `rev_county` or `rev_localauthority`, name not yet
settled — populated at intake and surfaced on the grant admin's location field, replacing the
disclosure-only reuse of `rev_locationarea` that revision 4 priced and the reviewer rejected.

## Why this is a change order, not rework against an existing task

`contract/wbs.json` task `wbs:0.4` (`contract/wbs.json` lines 241–246) names the seven Applicant/
Application/Review/Grant/Provider/Bank Account/Payment tables and their columns as built; it names
no county column. Reusing `rev_locationarea` would have been a disclosure change against an
existing column — sized as rework in revision 4 of `docs/plans/emily-review-feedback-2026-09-plan.md`
(line 1101, struck-through Δ4 note). **Reviewer decision 2026-09-18** rejects that reuse: it would
redefine a live 13-value closed Choice option set — shared with `rev_anonymisedstatistic` — rather
than merely gate its visibility. A new column is real schema-plus-form work with no comparable
existing WBS task, which is this project's own flag that a rework price undercounts
(`agents/commercial-agent.md` → "A deferred ROM is provisional by construction"). Plan citations:
`docs/plans/emily-review-feedback-2026-09-plan.md` line 1101 (detail, Δ5) and line 1265 (pricing
summary row).

## Two riders carried forward from the plan, not resolved by this document

- **No clean UK-wide county list exists.** ONS returns pseudo-codes for Scotland, Wales and unitary
  England — local authority may be the better attribute if the purpose is funder reporting (plan
  line 1101). This bears on naming (`rev_county` vs `rev_localauthority`), not on whether the column
  is built, and is unresolved as of this document.
- **The existing `rev_locationarea` option set is shared with `rev_anonymisedstatistic`** regardless
  of which column county lands on (plan line 1101) — noted so a later schema change to
  `rev_locationarea` does not overlook that second consumer.

## Historic backfill — smaller than the forward-fill, and separate

`rev_towncity`'s own description records that county is raw export column 23, dropped at intake by
choice, not absent from the source data (plan §"Trap 4", line ~933). For historic applications,
county may be recoverable by re-reading the export with no postcode lookup involved — materially
smaller than deriving it via EF-41. This document prices the forward-fill (new column + intake
population + admin surface) only; a historic backfill from column 23, if wanted, is a small
follow-on this document does not itemise and does not need EF-41 to unblock.
